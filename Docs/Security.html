Security Module

Appeal docs · Build, format, and usage guide

Prefix commands below with Security. All shown arguments are required. Results are available in Appeal expressions. Cryptographic errors return empty text or 0 and set status; unknown commands or invalid boolean syntax throw an interpreter error. The current plugin implements symmetric encryption/decryption; permissions and other future security services are not implemented.

Basic

CommandArgumentsBehavior
Generate_KeyReturn a fresh random 256-bit key as 43 URL-safe Base64 characters, without padding. Keep it outside encrypted data; no automatic key storage is performed.
EncryptPlaintext KeyReturn versioned authenticated encrypted text (APSEC1:...). A fresh nonce is generated for each call. Input may contain arbitrary bytes; maximum 16 MiB.
DecryptCiphertext KeyAuthenticate and decrypt a matching text envelope. Returns plaintext, or an empty string on failure. Empty plaintext can be valid: always inspect Security.Success.
Encrypt_With_PasswordPlaintext PasswordEncrypt with a fresh random salt and Argon2id-derived key. The version-1 format fixes Argon2id v1.3 at 2 passes and 64 MiB, independent of library default changes. Passwords must contain 1–1024 bytes.
Decrypt_With_PasswordCiphertext PasswordAuthenticate and decrypt a password-mode text envelope. Wrong credentials, malformed headers, and changed data fail.
Encrypt_FileSource Destination KeyStream-encrypt a regular file in 64 KiB chunks. Returns 1/0. Relative paths are under Resources; absolute paths are accepted. The destination folder must exist. Existing destinations are never overwritten.
Decrypt_FileSource Destination KeyAuthenticate and stream-decrypt a file, publishing its destination only after the authenticated FINAL marker and EOF are verified. Rejects modified, truncated, reordered, and appended data. Returns 1/0.
Encrypt_File_With_PasswordSource Destination PasswordPassword-derived-key variant of Encrypt_File; random salt, fixed versioned Argon2id parameters, and authenticated streamed output.
Decrypt_File_With_PasswordSource Destination PasswordPassword-derived-key variant of Decrypt_File. Failures remove staged output and preserve any existing destination.
Last_ErrorReturn a non-secret diagnostic for the previous operation, or an empty string on success. Does not clear status.
Backend_VersionReturn the library/backend version and publish Security.Backend_Version. Does not clear the previous operation status.

Read globals with Print_Global or Set_Var_Global. Keys and plaintext are returned directly, not published as globals or saved by the module. Script variables holding returned data remain ordinary interpreter strings.

Plugins

Test echoes every backend call with sensitive arguments redacted and returns clearly marked dummy data. It performs no real cryptography or file writes. Appeal_Sodium_Security uses libsodium: XChaCha20-Poly1305 for text, secretstream XChaCha20-Poly1305 for files, and Argon2id for password-derived keys. The same versioned data formats work across platforms.

The working plugin builds on Windows, Linux, and macOS. Windows and Linux runtime/interop tests are executed; macOS and mobile builds are not runtime-verified. Windows uses a static signed libsodium SDK, Linux may use a maintained system package or the matching locally built source. See the build guide for exact versions and dependency verification.

File and key handling

File output is staged in a private temporary sibling and published without overwriting existing paths. Windows uses an owner-only protected DACL and no-replace rename; POSIX uses mode 0600 and an atomic hard-link commit, requiring filesystem hard-link support. Derived keys, internal plaintext buffers, and owned secret-argument copies are wiped when released. Caller-owned script variables, original input files, process memory, key storage, and application permissions are outside this initial plugin's scope.
